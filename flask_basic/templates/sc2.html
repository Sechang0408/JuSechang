Before Base Model

일반적인 코드 설명

HTML에서 버튼을 클릭하면 JavaScript 이벤트가 실행됩니다. 이후 서버로 요청을 보내고, Flask에서는 라우터가 요청을 받아 처리한 뒤 결과를 다시 화면에 표시할 수 있습니다.

한계점

Flask와 JavaScript의 일반적인 흐름은 설명하지만, 이 프로젝트의 실제 파일명, 함수명, 모델 파일 구조는 반영하지 못합니다.

일반 설명 파일 구조 미반영 프로젝트 맥락 부족
After QLoRA Tuned Model

프로젝트 구조 기반 답변

sc1.html의 predictForm submit 이벤트가 실행되면 입력값을 기반으로 payload 객체가 생성됩니다. 이 payload는 fetch('/predict')를 통해 app.py의 /predict 라우터로 POST 요청됩니다. app.py는 preprocess_input() 함수로 입력값을 model_columns 순서에 맞게 정리하고, risk_model.pkl CatBoost 모델로 안전/주의/위험 이탈 위험군과 probabilities를 계산합니다. 마지막으로 sc1.html은 응답을 받아 결과 모달에 위험도, 주요 원인, 클래스별 확률을 표시합니다.

개선점

app.py, sc1.html, /predict, preprocess_input(), model_columns.pkl, risk_model.pkl 등 실제 프로젝트 구조를 반영합니다.

app.py sc1.html /predict risk_model.pkl
Training Pipeline

경로 4: Multi-Stage QLoRA 적용 흐름

전체 LLM을 다시 학습하지 않고, 4bit 양자화와 LoRA Adapter 학습을 활용해 제한된 GPU 환경에서도 도메인 특화 코드 챗봇을 구현했습니다.

01

Base Model

Qwen2.5-0.5B-Instruct 모델을 기본 대화 및 코드 설명 능력을 가진 출발점으로 사용했습니다.

02

4bit Quantization

모델을 4bit로 경량화해 Colab GPU 환경에서 메모리 부담을 줄이고 학습 가능하게 구성했습니다.

03

LoRA Adapter

전체 모델이 아니라 작은 Adapter만 학습하여 프로젝트 전용 지식을 반영했습니다.

04

Domain Chatbot

학습된 Adapter를 Base Model에 결합하여 OTT 프로젝트 전용 코드 설명 챗봇으로 사용합니다.
